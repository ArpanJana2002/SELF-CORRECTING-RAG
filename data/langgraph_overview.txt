LangGraph is a low-level orchestration framework for building stateful, multi-actor
applications with LLMs. It is built on top of LangChain and is designed for creating
agent and multi-agent workflows expressed as graphs.

Core concepts:
- StateGraph: the main graph object. You define a shared State (often a TypedDict or
  Pydantic model) that flows through the graph and is updated by each node.
- Nodes: plain Python functions (or Runnables) that take the current state and return
  a partial update to that state.
- Edges: connections between nodes. Edges can be direct (always go to node B after node A)
  or conditional (a router function inspects the state and decides which node to go to next).
- Cycles: unlike a simple DAG-based chain, LangGraph graphs can contain cycles, which is
  what allows an agent to loop — retrying a step, revising an answer, or calling a tool
  again — until some condition is met.
- Checkpointing / persistence: LangGraph supports persisting state between runs, which
  enables features like human-in-the-loop approval, time travel, and long-running
  multi-session agents.

Corrective RAG (CRAG) is a pattern implemented on top of LangGraph where a document
grader evaluates whether retrieved chunks are actually relevant to the question. If the
retrieved documents are insufficient, the agent rewrites the query and falls back to a
web search tool to fill the gap before generating an answer. This "self-correction" loop
continues, bounded by a maximum number of iterations, until the agent produces an answer
that is both grounded in retrieved facts (no hallucination) and actually resolves the
user's question.

Self-RAG is a related pattern where the model itself decides, at generation time, whether
it needs to retrieve, and afterwards grades its own output for factual grounding and
usefulness, regenerating or re-retrieving as needed.
